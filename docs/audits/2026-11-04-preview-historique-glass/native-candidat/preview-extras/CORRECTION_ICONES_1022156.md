# Correction de l'encodage des icônes après 1022156

La capture 1022156 montre trois caractères de remplacement sur chacune des tuiles. Cause confirmée dans le Smali livré : `\ufffd\ufffd\ufffd` remplaçait chaque symbole, parce que la compilation ECJ de ces deux composants avait été lancée sans `-encoding UTF-8`. Les tests JVM compilaient correctement les sources en UTF-8, mais ne comparaient pas les chaînes de leurs Smali embarqués. Des accents des messages et descriptions de `PreviewPlayerMode` et `PreviewPlayerTiles` étaient aussi corrompus ; notamment, la description du like ne correspondait plus au texte recherché par le dessin du cœur.

Correction : recompilation des mêmes deux sources avec ECJ `-encoding UTF-8`, mise à jour des Smali et de leurs empreintes. Par rapport à 1022156, seuls des littéraux `const-string` diffèrent dans ces composants : symboles des tuiles et textes accentués rétablis ; aucune commande, logique, vue ou écouteur modifié. Les tuiles File, Paroles et Appareils restent indisponibles, conformément à l'audit précédent ; Volume reste local. Horloge, seek et commandes de lecture restent inchangés.

`test_compiled_text.py` échouait sur l'ancien Smali ; il vérifie maintenant les quatre symboles, les chaînes françaises et l'absence de caractères de remplacement dans tous les Smali de ces deux classes. La CI l'exécute sur les Smali versionnés **et** après décodage de l'APK. Les tests JVM sont complémentaires : ils ne suffisent pas à vérifier le code embarqué. Toute recompilation future de ces sources doit explicitement utiliser `-encoding UTF-8`, puis exécuter ce test sur l'APK décodée.

Validation locale : APK non signée assemblée et décodée, test des chaînes compilées et 13 tests du lecteur réussis ; garde des sept fichiers protégés 7/7 ; contrôleur, MainActivity et shell comparés identiques avant/après ; simulations JVM et 31 tests Node réussis. Le rendu des symboles selon la police Android, le cadrage et les interactions ne sont **pas validés sur téléphone**.
