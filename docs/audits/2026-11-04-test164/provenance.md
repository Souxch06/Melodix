## Événements : état réellement démontré

- Démarrage sans session : garde native ferme l'accès privé, mais bloque aussi le shell. Nettoyage JS complet non démontré.
- Début de vérification / refus / expiration / restauration échouée : transition native non valide appelle le reset ; l'identité des requêtes et caches JS à travers cette frontière reste non démontrée. Une absence ou erreur HTTP isolée n'est pas forcément une expiration.
- Déconnexion : `MainActivity.A` avance la génération et nettoie les vues ; le code JS ne reçoit pas directement une invalidation atomique. La route login JS reconnue nettoie désormais certains stores, mais cette observation peut être absente ou tardive.
- Retour activité / rotation : `resume` relance la vérification depuis 3 ; pas de preuve de non-restauration pour toutes les combinaisons de vues, de WebView et de retour de requête.
- Réponse réseau tardive : une requête bibliothèque JS annulée lors d'une route login reconnue est rejetée dans la fixture existante. Une charge produite sous une ancienne session puis reçue sous une nouvelle session n'est pas distinguée à la frontière native ; voir le probe en échec. Le service média a une voie séparée.

## Conditions avant ouverture du shell

Définir un contrat de provenance attaché à chaque requête et publication, valide à émission/réception/application, y compris profile/player/recherche, fallback Home et service média ; invalider à chaque événement natif et à la recréation sans injecter de scripts sur les domaines externes ni effacer les préférences/cookies. Établir une frontière WebView défendable aussi pour les frames. Séparer ensuite routes publiques et charges privées et reconstruire un état neutre cohérent ; tester de vraies transitions, puis seulement lever les gardes une par une. Le correctif ciblé des caches sur route login n'est pas suffisant pour ouvrir le root.
